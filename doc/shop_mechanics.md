# 商城與道具運作邏輯說明文件 (Shop & Item Mechanics Documentation)

本文件詳述《浪跡戰域》中的商店系統（加值商城、黑市交易所）以及道具獲取與使用的核心邏輯。

---

## 1. 星空加值商城 (Premium Shop)

加值商城提供具有時效性的增益效果（Buff），幫助玩家在戰鬥、探索或資源獲取上取得優勢。

### 核心貨幣
*   **台灣藍寶靈石 (Premium Gems)**：💎
    *   來源：活動獎勵、週任務報酬、或直接儲值。

### 購買邏輯
*   所有加值道具皆透過 `secure_purchase_premium_item` RPC 進行後端驗證與扣款。
*   **生效機制**：購買後立即生效，持續 **24 小時**。
*   **時間疊加**：若在 Buff 生效期間重複購買，有效時間將會順延。

### 道具詳細邏輯 (Item Usage & Trigger Logic)

| 道具名稱 | 核心鍵 (Key) | 觸發機制與詳細邏輯 |
| :--- | :--- | :--- |
| **冥幽七里香** | `eliteEncounterExpiry` | **獨立機率觸發**：在「自動探索」模式下，每次移動觸發遇敵檢查時，系統會先進行一次獨立的 2% 機率判定。若判定成功，不論原本遇敵結果為何，皆會強制生成「菁英怪」戰鬥。 |
| **高鐵通行票** | `hsrPassExpiry` | **移動速度加成**：搭乘火車進行城市間移動時，移動速度常數由 `TRAVEL_SPEED_MPS` 變為 `2x`（即時間減半）。生效期間，玩家在地圖上的圖示會由火車 `🚂` 變更為高鐵 `🚄`。 |
| **幸運四葉草** | `luckyCloverExpiry` | **掉落率修正**：由後端 `secure_resolve_combat` RPC 於結算時判定。素材掉落率由基礎值（如 20%）提升至 **24%**。此為全域素材掉落機率修正。 |
| **女神的恩典** | `goddessBlessingExpiry` | **經驗獲取加成**：同樣由後端結算 RPC 控制。當戰鬥勝利時，所有參戰或上陣夥伴獲得的經驗值（EXP）將會進行 `x1.2` 的加成計算。 |
| **豐饒角** | `hornOfPlentyExpiry` | **產量隨機倍增**：僅在「自動探索」獲得勝利時觸發。結算時會隨機產生一個 `1.0x` 到 `1.5x` 之間的倍率，將該次獲得的金幣與資源放大。額外獲得的部分會於 UI 中標示為 `(+Bonus Gold)`。 |

## 2. 黑市交易所 (Market)

黑市是玩家處理多餘裝備的主要場所。

### 交易模式
*   目前僅開放 **裝備收購 (Sell)** 功能。
*   **價格公式**：`100 * 5^(稀有度 - 1)`
    *   Rarity 1 (普通): 100 G
    *   Rarity 2 (精良): 500 G
    *   Rarity 3 (稀有): 2,500 G
    *   Rarity 4 (史詩): 12,500 G
    *   Rarity 5 (傳說): 62,500 G
*   **限制條件**：正在裝備中的道具無法出售，必須先卸下。

## 3. 城鎮設施交易 (City Facilities)

雖然不屬於「商城」按鈕，但玩家主要透過以下設施「購買」或「交換」成品：

### 鍊金試驗所 (Alchemy)
*   **功能**：將低階材料與金幣轉化為消耗性道具（如藥水、永久屬性種子）。
*   **代表道具**：
    *   各種等級的生命/魔力藥水。
    *   力量/鐵壁種子、生命之果（永久提升數值）。

### 鐵匠鍛造坊 (Blacksmith)
*   **功能**：消耗特定區域素材與大量金幣，鍛造強力裝備。
*   **邏輯**：不同城市提供不同的鍛造配方（例如：台北產武器、新北產盔甲）。

## 4. 道具分類與限制 (Item Categories)

| 分類 | 說明 | 堆疊 | 備註 |
| :--- | :--- | :---: | :--- |
| **Potion (藥水)** | 戰鬥中或地圖上恢復 HP/MP。 | 可 |
| **Consumable (消耗品)** | 使用後永久提升數值（種子類）。 | 可 |
| **Material (材料)** | 用於鍛造、鍊金或升級設施。 | 可 |
| **Equipment (裝備)** | 提供 ATK/DEF/HP 加成。 | 不可 | 具備五種稀有度。 |
| **Gem (寶石)** | 高階合成材料。 | 可 |

## 5. 技術實現細節 (Technical Implementation)

*   **資料儲存**：
    *   Buff 狀態儲存於 `profiles` 表的 `active_buffs` (JSONB) 欄位中。
    *   每個 Buff 存儲過期時間戳（Unix Timestamp ms）。
*   **前端同步**：
    *   購買成功後會調用 `refreshProfile` 立即更新本地狀態。
    *   `PremiumShopModal` 會根據目前時間計算並顯示剩餘有效分鐘/小時。
*   **安全驗證**：
    *   所有涉及金額扣除的行為均在 Supabase RPC 層級執行，防止前端篡改價格或餘額。
